## 2. 启动前需要哪些资料

读取入口 [`DocumentReader.read`](../../src/hara_agent/services/extraction/document_reader.py) 只接受 `.docx/.pdf`。参考HARA工作簿不是Item输入；没有文本层的扫描PDF也不能假定当前读取器会自动OCR。

| 文件/目录 | 作用 |
| --- | --- |
| Item Definition | 项目事实来源，保留原始文件和内容哈希；换内容须开新运行 |
| `method_assets/fusa_baseline_v1/manifest.yaml` | 默认方法入口，引用资产及哈希必须完整 |
| `references/HARA_Template_AI_20260327.xlsx` | 默认报告样式/结构模板 |
| `.env`或进程环境 | 本机Provider配置与密钥，不提交 |
| `runtime/agent/` | 默认checkpoint与运行级响应缓存，需要可写和足够空间 |
| `runtime/review/` | 默认审核、来源和计算追溯，交付时与报告一起保留 |
| 独立输出目录 | 每次新运行使用新Run ID、新Excel和日志 |

[`MethodSourceResolver.resolve`](../../src/hara_agent/method_sources/resolver.py) 统一处理两种方法来源：传 `--template` 时该工作簿经角色编译成为方法并兼作报告模板；不传时用YAML编译方法、用 `--report-template` 提供报告布局。`--template` 不是单纯“换皮肤”；方法哈希与报告模板哈希在YAML模式下彼此独立。

## 3. 配置读取和优先顺序

[`cli.main`](../../src/hara_agent/cli.py) 先调用 [`load_local_env`](../../src/hara_agent/config/env_file.py)，再解析CLI；[`LLMConfig.from_env`](../../src/hara_agent/config/llm_config.py) 读取Provider参数，[`RunConfig`](../../src/hara_agent/config/run_config.py) 承载运行参数。

1. 已存在的进程环境变量优先。
2. 当前工作目录 `.env` 使用 `os.environ.setdefault` 补缺，不覆盖进程变量。
3. 缺项使用代码默认值。
4. CLI参数构造RunConfig，不提供 `--model/--api-key` 等Provider覆盖参数。

所以修改 `.env` 后，旧终端若仍导出同名变量，可能继续用旧配置。不要通过打印API key排查。嵌入Python调用 `HARAApplication.from_env` 时，如需读取 `.env`，必须先调用 `load_local_env()`；类方法本身不加载文件。

`.env` 支持空行、整行注释、`export NAME=value` 和成对引号，不支持完整shell展开，也不去掉行尾注释。`API_KEY=abc # 注释` 会把注释一起读成值。仅在本地填写真实配置：

```dotenv
HARA_LLM_PROVIDER=volcengine-agent-plan
HARA_LLM_BASE_URL=REPLACE_WITH_PROVIDER_HTTP_ENDPOINT
HARA_LLM_MODEL=REPLACE_WITH_AUTHORIZED_MODEL_ID
HARA_LLM_API_KEY=REPLACE_LOCALLY
```

## 6. 有界样本和8路全量

普通链是：抽取→功能/引导词/失效→基础候选→必要物理方案及实例化/物理预计算→因果→缺失风险事实→S/E/C及分支ASIL→SG/Safe State/FTTI→质量门/报告。物理方案不是统一在因果之后。入口见 [`build_hara_agent_graph`](../../src/hara_agent/workflow/semantic_graph.py)、[`assess_scenarios`](../../src/hara_agent/workflow/nodes/scenarios.py)、[`construct_physical_scenarios`](../../src/hara_agent/workflow/physical_analysis.py)。

以下会付费，仅在明确授权并已设置变量后执行。变量保护会让未配置的复制粘贴停止：

```bash
: "${HARA_TASK_ITEM:?填写本次已确认输入路径}"
: "${HARA_TASK_RUN_ID:?填写新样本Run ID}"
: "${HARA_TASK_MODE:?填写来源支持的模式}"
: "${HARA_TASK_APPROVED_CALLS:?填写本轮授权请求上限}"
mkdir -p output/review_sample
set -o pipefail
.venv/bin/python -u -m hara_agent analyze \
  --item "$HARA_TASK_ITEM" \
  --method-baseline method_assets/fusa_baseline_v1/manifest.yaml \
  --report-template references/HARA_Template_AI_20260327.xlsx \
  --output "output/review_sample/${HARA_TASK_RUN_ID}.xlsx" \
  --run-dir runtime/agent --run-id "$HARA_TASK_RUN_ID" \
  --operating-mode "$HARA_TASK_MODE" --allow-draft --max-workers 1 \
  --sample-function-limit 1 --sample-malfunction-limit 1 \
  --sample-parent-scenario-limit 1 --sample-scenario-pair-limit 8 \
  --provider-attempt-limit "$HARA_TASK_APPROVED_CALLS" \
  2>&1 | tee "output/review_sample/${HARA_TASK_RUN_ID}.log"
```

1功能/1失效/1父场景不等于1请求：物理取点、人员分支、事实补全及重试都可能增加调用。样本和全量同策略，不能为样本私填碰撞值或批准状态。

### 6.1 当前8路+硬预算的真实边界

[`HARAApplication.from_env`](../../src/hara_agent/application.py) 只有 `bounded_sample=true` 才自动建预算账本：

- 普通非样本 `analyze --max-workers 8` 会调用模型，但默认没有逐HTTP硬预算账本。
- `--provider-attempt-limit N --max-workers 8` 不会变成“有预算全量”；它触发样本校验并拒绝8路/缺失样本limits。
- 8路全范围且统一记录/限额，使用已有client/budget依赖注入；不是新运行时或新CLI。

下面是受控调用骨架，只有替换占位并获得对应授权后执行：

```python
from pathlib import Path
from hara_agent.application import HARAApplication
from hara_agent.config import LLMConfig, RunConfig, load_local_env
from hara_agent.infrastructure.llm.factory import create_llm_client
from hara_agent.infrastructure.llm.provider_budget import ProviderAttemptBudget

run_id = "REPLACE_WITH_NEW_RUN_ID"
approved_attempts = int("REPLACE_WITH_EXPLICIT_AUTHORIZED_TOTAL")
run_dir = Path("runtime/REPLACE_WITH_RUN_DIRECTORY")
config = RunConfig(
    item_path=Path("/REPLACE/WITH/CONFIRMED_ITEM.pdf"),
    template_path=None,
    output_path=Path("output/REPLACE_WITH_NEW_REPORT.xlsx"),
    run_dir=run_dir, run_id=run_id, operating_mode="REPLACE_WITH_CONFIRMED_MODE",
    allow_draft=True, max_workers=8,
    # 不在RunConfig设置sample limits或provider_attempt_limit。
)
load_local_env()
config.validate()
budget = ProviderAttemptBudget(
    run_dir / f"{run_id}.provider-attempts.jsonl",
    run_id=run_id, limit=approved_attempts,
)
client = create_llm_client(LLMConfig.from_env(), attempt_budget=budget)
result = HARAApplication(config, client).run()
```

依据是 [`ProviderAttemptBudget.begin`](../../src/hara_agent/infrastructure/llm/provider_budget.py)：每次HTTP前预留额度，失败也计数。授权、账本归属、配置和停止原因应一起存档；子run必须共享原账本，不换Run ID重置。临时runner不是稳定CLI。历史共享账本恢复还需沿原调用入口，不能用普通CLI替换注入配置。

## 7. 日志、账本与缓存

[`OpenAICompatibleClient`](../../src/hara_agent/infrastructure/llm/openai_compatible.py) 在stderr记录任务、尝试、字符、上限、思考选项和usage；[`WorkflowGraph.run`](../../src/hara_agent/workflow/graph.py) 记录阶段。`-u`和 `2>&1 | tee` 同时显示终端及文件；已有后台运行可在另一个终端 `tail -F 已确认的日志路径`。后台在跑不等于IDE当前终端会自动显示。

| 产物 | 位置 | 意义 |
| --- | --- | --- |
| checkpoint | `<run-dir>/<run-id>.checkpoint.json` | 最后原子提交状态，不是最后HTTP返回 |
| Provider账本 | `<run-id>.provider-attempts.jsonl` | 仅注入budget的调用有；started先于发送 |
| 原始返回 | `<run-id>.provider-attempts.responses/000001.json` | 原HTTP信封或失败片段，与成功缓存分开 |
| 响应缓存 | `<run-id>.physical-responses/`、`.scenario-responses/`、`.risk-fact-responses/` | 命中仍做契约/语义验证 |
| 审核资料 | `<review-root>/<run-id>/` | functions、malfunctions、scenario_candidates、scenario_feasibility、risk_execution_trace、summary等 |
| 抽取缓存 | `HARA_ARTIFACT_CACHE_DIR` | 原始候选隔离在candidates，不当成已验证事实 |

缓存权威为 [`ResponseCheckpoint.complete`](../../src/hara_agent/infrastructure/llm/response_checkpoint.py)、[`ValidatedArtifactCache`](../../src/hara_agent/services/extraction/artifact_cache.py)。不能把历史累计physical_analysis_metrics再加进当前账本；推理属于输出、Provider缓存输入属于输入，不重复相加。失败无usage/中断未记结束要写未知，不能补0。并发请求耗时之和不是墙钟时间。

8路不保证8倍加速。不要让多个准备进程各读一份GB源checkpoint造成swap。也不要多个独立进程任意写同一run状态：原子替换防半文件，不提供业务状态的多写者合并。

## 8. 中断恢复

[`CheckpointRepository`](../../src/hara_agent/workflow/checkpoints.py) 用临时文件、flush/fsync和原子替换；[`WorkflowGraph.run`](../../src/hara_agent/workflow/graph.py) 在耗尽预算时回到最后提交状态并保存原因。HTTP返回已存而阶段未提交是可能的，恢复应命中响应缓存。

恢复前确认：原输入字节、来源选择策略、方法资产和模板不变；保留Run ID/run-dir/review-root/缓存/账本；样本所有limit、IDs、pair limit和预算与原scope一致；模型路由/思考配置等与绑定context一致；有当前有效授权与余量。然后原命令增加 `--resume`。注入budget的全量继续同一受控入口，设置 `resume=True`并复用原账本。

校验见 [`HARAApplication.run/bounded_source_context`](../../src/hara_agent/application.py)。`Bounded sample inputs, method, or Provider configuration changed` 应查真实差异，不删guard/改旧哈希。换Item内容、对象、方向或阶段应新建运行或走差异验证；不能用恢复继承旧结论。

[`HARAState.read_committed/from_dict`](../../src/hara_agent/workflow/state.py) 有不同语义：前者只读已提交状态，适合离线投影；后者用于恢复，Scenario/因果契约不兼容时保留上游、失效场景/风险/SG并回到MALFUNCTIONS。旧文件可读不代表旧结论可继续，恢复可能需要新请求和预算。

响应键包括提示、schema、有效路由/模型，物理独立推理策略也参与；凭据不参与。语义变化后不命中通常正确。旧格式兼容不能把旧返回冒称新提示真实验证。不要清空历史来“修缓存”。

## 9. 零Provider重导与重评分

### 9.1 只生成新Excel

[`OfflineReportRebuilder.rebuild`](../../src/hara_agent/services/reporting/offline_rebuild.py) 读取已提交状态和review/trace，不补因果或物理输入。需要原方法快照和报告样式：

```bash
.venv/bin/python -m hara_agent rebuild-report \
  --review-run-id SOURCE_RUN_ID \
  --checkpoint /ABS/PATH/SOURCE_RUN_ID.checkpoint.json \
  --baseline /ABS/PATH/ORIGINAL_METHOD/manifest.yaml \
  --report-style-template references/HARA_Template_AI_20260327.xlsx \
  --schema report_assets/hara_report_v1.yaml \
  --review-root /ABS/PATH/ORIGINAL_REVIEW_ROOT \
  --output output/NEW_REBUILT_REPORT.xlsx \
  --audit-output-dir output/NEW_REPORT_AUDIT
```

`--causal-trace`指向已有追溯；`--synthesis-candidates`和`--speed-context-audit`须成对。输出新文件，保留旧报告，不手修一次Excel代替修生成器。

### 9.2 重算确定性风险

[`OfflineRiskRescorer.run`](../../src/hara_agent/workflow/risk_rescoring.py) 保留上游已验证场景/因果，仅重算评分及下游，必须用新target和输出。原风险与有效队列要一一对应，来源/指纹完整：

```bash
.venv/bin/python -m hara_agent rescore-risk \
  --source-run-id SOURCE_RUN_ID --target-run-id NEW_RESCORE_RUN_ID \
  --checkpoint /ABS/PATH/SOURCE_RUN_ID.checkpoint.json \
  --source-baseline /ABS/PATH/ORIGINAL_METHOD/manifest.yaml \
  --baseline /ABS/PATH/REVIEWED_TARGET_METHOD/manifest.yaml \
  --report-style-template references/HARA_Template_AI_20260327.xlsx \
  --run-dir runtime/rescore --review-root runtime/review \
  --output output/NEW_RESCORED_REPORT.xlsx
```

`--source-baseline`是受控方法迁移的原基线证明，不是任意换规则的豁免。输入搬家可传 `--item`，内容哈希必须相符。新增运动/控制事实不能用risk-input-supplement直接继承旧因果，仍需差异验证。重导、重评分、真实重验三种证据分开。

## 10. 排查入口与交班清单

| 现象 | 首查 |
| --- | --- |
| 模块找不到 | Python路径、editable安装，避免系统pip与venv混用 |
| env修改不生效 | 进程变量优先级、工作目录，不打印key |
| 401/订阅/额度 | Provider真实错误，doctor不验余额；`LLMQuotaExceededError`不循环重试 |

| 预算耗尽 | started计数、停止原因，原账本恢复 |

| 运行慢/内存交换 | 看阶段实际调用、纠正、上下文、准备/落盘，不只加并发或砍输出 |

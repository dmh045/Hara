# 当前语义任务与执行职责

## 当前生产链中的模型任务

下表按职责区分请求，不意味着每条风险都要独立调用所有 Agent。抽取按资料和缺口、失效按功能偏差、物理按可复用方案、因果按具体身份、风险事实按缺项调度；任务次数由实际输入和缓存决定。

| 职责 | 当前实现 | 允许生成的内容 | 不承担的职责 |
|---|---|---|---|
| 核心资料与功能联合提取 | [ItemArtifactExtractionAgent](../../../src/hara_agent/services/semantic/item_artifact_agent.py) | 有来源的Item事实、功能及缺口 | 用模板例子填产品规格 |
| 有界资料补查 | [ItemSupplementAgent](../../../src/hara_agent/services/semantic/item_supplement_agent.py) | 从选定证据中补充遗漏的事实类型 | 无界遍历或新建事实权威 |
| 方法所需项目事实定向提取 | [TargetedProjectFactExtractionAgent](../../../src/hara_agent/services/semantic/targeted_project_fact_agent.py) | 方法需要且原文可支持的具体事实 | 生成碰撞速度、风险等级 |
| 引导词适用性 | [GuidewordApplicabilityAgent](../../../src/hara_agent/services/semantic/guideword_agent.py) | 功能与偏差的适用、排除或未决判断 | 把所有组合默认保留 |
| 失效及车辆危险行为 | [MalfunctionHazardAgent](../../../src/hara_agent/services/semantic/malfunction_agent.py) | 通过准入的功能偏差、车辆行为与危险主张 | 未经具体场景验证就确定最终风险 |
| 故障后物理方案 | [PhysicalScenarioAgent](../../../src/hara_agent/services/semantic/physical_scenario_agent.py) | 模型、对象、参数假设、剩余控制；已有运动时仅补控制或纠正受影响响应 | 最终S/E/C/ASIL、工程批准 |
| 具体场景因果 | [ScenarioFeasibilityAgent](../../../src/hara_agent/services/semantic/scenario_agent.py) | 失效→行为→交互→危险的因果链与依赖 | 用一次父场景结论覆盖改变后的全部世界 |
| 风险事实解释 | [ScenarioRiskFactAgent](../../../src/hara_agent/services/semantic/scenario_risk_fact_agent.py) | 评分仍缺且可由证据解释的输入与找不到的结果 | 用默认值替代NOT_FOUND或自行查表定级 |

SG意图登记、Safe State响应检查、FTTI时间求解和Excel投影属于已有确定性或受方法约束的下游职责，不因表格缺值就新增模型任务。当前生产调用见 [HARAApplication](../../../src/hara_agent/application.py)、[场景节点](../../../src/hara_agent/workflow/nodes/scenarios.py)与[物理调度](../../../src/hara_agent/workflow/physical_analysis.py)。

## 三种物理请求为何共用一个实现

| 本次任务 | 发送的核心上下文 | 何时继续因果或计算 |
|---|---|---|
| 完整运动方案 | 失效机制、对象和运行条件、有效方法模型目录、来源限制 | 完成实例化及物理相容检查后 |
| 控制补全 | 已有固定轨迹、相关人员/控制依赖和待补字段 | 不擅改已有运动；控制改变危险主张时按现有机制重验 |
| 响应纠正 | 当前不安全或不一致的响应、程序诊断和受影响分支 | 保留原始返回与有限纠正，不能靠扩大能力或改距离制造成功 |

是否需要新请求由现有 `task_scope` 与工作流缓存判断。代码实例P03解释这条路由；R01解释驾驶员因果复用；O01/O02解释响应缓存和实际请求预算。正文的解释不意味着所有路径已在五个项目中以相同频率触发。

## 真实开销如何归属

模型调用的首次请求、结构修复、语义纠正和传输重试均计入Provider账本。输入Token包含Provider报告的缓存输入，输出Token包含推理Token，不能重复相加。文档整理、Codex监控和离线评分没有计入Provider消耗。最新五份结果来自此前全量加定向修订；当前定向账本并不是五份项目从头运行的成本总和。准确数字与范围见“时间、Token与复用”章节。

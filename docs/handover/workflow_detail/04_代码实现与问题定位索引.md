## 怎么使用这些实例

本文中的“实现例”是**当前生产代码的连续摘录**，不是另外设计的一套示意实现。生产基线固定为 `d6a400e7010d62ff5dda56efd8215f23729bb3ec`；链接中的行号对应这个提交。片段为了阅读可以去除共同缩进，没有省略中间语句。它们依赖所在类、调用方和数据契约，不能直接复制为独立脚本运行。

每个例子按“调用位置 → 输入与输出 → 实际代码 → 行为解释 → 现有测试”阅读。先看代码解决哪一个问题，再看它没有解决哪些问题。例如，命中响应缓存证明没有再次发送同一请求，不证明旧因果结论适用于一个已经改变的物理世界。

HTML 的各流程步骤中直接放置对应实例；下表可一键跳转。下面的索引同时保留源码和测试定位，不需要在几千行文件里凭关键词猜入口。生成文档时会把每个摘录与源码逐行比较；片段、行号或源码变化后必须重新核对，不允许静默展示过期示例。

## 实现例 O01｜相同并发请求为什么只发送一次

生产调用中，语义 Agent 通过 `ResponseCheckpoint.complete()` 取得保存响应或发送请求。输入包括完整 `LLMRequest`、客户端有效配置以及是否只读缓存；输出是一个响应或缓存未命中时的 `None`。下面只摘录身份生成与加锁部分，缓存读取、校验及落盘继续在 `_complete_locked()` 中执行。

<!-- source-example: src/hara_agent/infrastructure/llm/response_checkpoint.py:L27-L49 -->

```python
def complete(self, client, request, *, cache_only=False):
    config = getattr(client, "config", None)
    # Full prompt/schema identity includes source facts, method and scenario
    # IDs. Credentials are neither part of the key nor written to disk.
    effective_request = asdict(request)
    # Batch position and retry permission do not change the model input.
    # An exact successful response stays usable with stricter retry policy.
    effective_request["metadata"] = {key: value for key, value in effective_request["metadata"].items()
        if key not in {"parent_batch", "split_path", "split_depth", "strict_no_format_retry"}}
    material = {"request": effective_request, "route": {
        key: getattr(config, key, "") for key in ("provider", "base_url", "model", "scenario_thinking")
    }}
    if request.task == "construct_post_fault_physical_scenario":
        material["route"].update(physical_reasoning_identity(config))
    key = hashlib.sha256(json.dumps(material, ensure_ascii=False, sort_keys=True,
                                   separators=(",", ":"), default=str).encode()).hexdigest()
    path = self.directory / f"{key}.json"
    # Same in-flight request in concurrent workers must not pay twice on a
    # cache miss. Atomic rename below still protects interrupted writes.
    with _request_lock(path):
        if cache_only and not path.is_file():
            return None
        return self._complete_locked(client, request, path, key)
```

`effective_request` 保留实际提示、Schema 和元数据，仅去掉代码列出的批次位置／重试许可字段。物理任务另外纳入有效思考配置，防止 low、disabled 等配置串用缓存。相同路径由同一进程内的锁串行进入缓存检查，因此并发首次未命中也不会同时发送四遍；不能把这里的线程锁描述成跨主机分布式锁。

**具体例子：** 四个线程提交相同请求，第一次实际调用客户端，其余三个读取已保存响应。读取返回的本次 usage 为零；历史付费消耗仍由原账本保留，不能据此抹掉之前的成本。请求内容或有效物理推理配置改变时，不能期待仍然命中。

**源码与验证：** [`ResponseCheckpoint.complete`](../../../src/hara_agent/infrastructure/llm/response_checkpoint.py#L27)、[`_complete_locked`](../../../src/hara_agent/infrastructure/llm/response_checkpoint.py#L51)；[四线程只调用一次的现有测试](../../../tests/unit/test_reuse_reporting_acceptance.py#L86)与[思考模式隔离和缓存命中测试](../../../tests/unit/test_physical_reasoning_policy.py#L128)。这证明请求复用，不证明可以绕过语义校验或继承旧批准。

## 实现例 O02｜重试和断点恢复为什么不会重置预算

[`OpenAICompatibleClient` 的传输循环](../../../src/hara_agent/infrastructure/llm/openai_compatible.py#L703)在每次 HTTP 尝试前调用 `ProviderAttemptBudget.begin()`。下面是该函数在持有线程锁和账本文件锁后，重新核对历史计数、检查上限并写入预留记录的部分。

<!-- source-example: src/hara_agent/infrastructure/llm/provider_budget.py:L105-L129 -->

```python
        event = json.loads(line)
        if event.get("run_id") != self.run_id:
            raise ValueError("Provider attempt ledger is bound to a different run")
        attempts += event.get("event") == "attempt_started"
    self._attempts = attempts
    if self.limit is not None and attempts >= self.limit:
        raise ProviderAttemptBudgetExceeded(
            limit=self.limit, attempts=attempts,
            ledger_path=self.path,
        )
    attempt_id = attempts + 1
    self._write_locked(descriptor, {
        "event": "attempt_started",
        "run_id": self.run_id,
        "attempt_id": attempt_id,
        "recorded_at": datetime.now(timezone.utc).isoformat(),
        "task": request.task,
        "schema_name": request.schema_name,
        "model": model,
        "request_options": request.metadata.get("_provider_options", {}),
    })
    self._attempts = attempt_id
    self._session_attempts += 1
    return attempt_id
finally:
```

**具体例子：** 上限为两次，第一次网络失败、第二次成功，两次都占额度。恢复相同 `run_id` 和账本后再次请求会在发送前抛出 `ProviderAttemptBudgetExceeded`。进程在拿到响应前退出，已经写入的 `attempt_started` 也不会退回额度，避免恢复后低估真实尝试。

**调用边界：** 这个保护要求客户端实际装配了账本；不能看到类存在，就声称所有普通 CLI 全量天然带相同硬上限。`limit=None` 表示记录但不设次数上限，授权来自调用方，不是旧账本自动赋予。`finish()` 保存 usage，原始响应另存，不能把响应未知的请求记为零消耗。

**源码与验证：** [`ProviderAttemptBudget.begin`](../../../src/hara_agent/infrastructure/llm/provider_budget.py#L89)、[`finish`](../../../src/hara_agent/infrastructure/llm/provider_budget.py#L133)；[网络重试及恢复后超限反例](../../../tests/unit/test_bounded_production_run.py#L38)、[子阶段共享同一账本](../../../tests/unit/test_bounded_production_run.py#L190)。

## 实现例 O03｜业务 checkpoint 如何避免写到一半损坏旧文件

工作流通过 `CheckpointRepository.save(state)` 保存已经形成的业务状态。函数先调用 `state.to_dict()` 编码，再在目标目录创建临时文件；下面摘录写入、同步与替换。调用方仍负责决定“哪些结果已经可以提交到状态”，文件写入本身不做因果批准或风险评分。

<!-- source-example: src/hara_agent/workflow/checkpoints.py:L36-L53 -->

```python
handle, temp_name = tempfile.mkstemp(
    prefix=f".{state.run_id}.", suffix=".tmp", dir=str(self.run_dir), text=True
)
try:
    with os.fdopen(handle, "w", encoding="utf-8") as stream:
        stream.write(payload)
        stream.flush()
        syncing = time.perf_counter()
        os.fsync(stream.fileno())
        synced = time.perf_counter()
    for attempt in range(5):
        try:
            os.replace(temp_name, target)
            break
        except PermissionError:
            if attempt == 4:
                raise
            time.sleep(0.05 * (attempt + 1))
```

**具体例子：** 写临时文件时中断，原 checkpoint 仍是上一版；写完后通过同目录 `os.replace()` 替换。遇到 `PermissionError` 时仅有限重试文件替换，不重新调用 Provider。原子替换并不提供多写入者业务合并，因此并发任务结果仍需由 workflow 的收集和保存流程统一提交。

**源码与验证：** [`CheckpointRepository.save/load`](../../../src/hara_agent/workflow/checkpoints.py#L28)、[`WorkflowGraph` 保存入口](../../../src/hara_agent/workflow/graph.py#L109)；[因果批次中断后复用](../../../tests/unit/test_scenario_incremental_checkpoint.py#L86)、[某并行任务失败后仍保存已完成任务](../../../tests/unit/test_scenario_incremental_checkpoint.py#L140)、[预算停止返回最后已提交状态](../../../tests/unit/test_bounded_production_run.py#L165)。这些测试验证相关流程的保存/恢复行为，不等于对所有操作系统做过断电故障测试。

## 接手者如何完成一次不付费的代码定位

以“FTTI 有些成员仍无数值”为例：

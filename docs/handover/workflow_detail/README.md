## 3. 重新构建

直接阅读HTML不需要Python或联网。修改源文后，在完整仓库中使用独立文档环境：

```bash
python3.12 -m venv /tmp/hara-doc-build
/tmp/hara-doc-build/bin/python -m pip install Markdown beautifulsoup4
/tmp/hara-doc-build/bin/python docs/handover/workflow_detail/build_report.py \
  --output docs/handover/HARA_Workflow_Engineering_Detail_20261124.html \
  --qa-output /tmp/hara-workflow-html-check.json
```

不再需要原参考HTML或 `--reference` 参数。源码和测试链接固定生产提交；文档维护文件链接跟随仓库master，最终交付提交号及文件哈希另记录在交接包manifest。以后若修改业务代码，要先复核源码摘录和说明，再更新构建器中的生产基线。

真实摘录采用 `source-example: 路径:L起行-L末行` 标记，紧跟Python代码块；构建器同时比较工作树及固定Git提交，只允许整体去共同缩进，不允许漏行或修改原代码。实例总索引自动形成 `code-e01` 等稳定锚点，不手工维护第二份行号清单。

本机文档依赖位于 `tmp/handover_render_tools`，没有修改项目requirements、pyproject、.env或模型配置。样式独立维护、最终内嵌HTML，转发时不依赖外部CSS或图像服务。

流程图使用能随页面宽度换行的原生HTML结构，不把固定尺寸SVG里的长文字缩成小字。每张图包含标题、方向说明、处理条件和结果去向，关键步骤可跳转到对应实现章节。窄屏时并列分支改为纵向排列；正文、图和代码索引均可直接离线阅读，无外部脚本。目录交互脚本内嵌在同一HTML内；禁用JavaScript时，章节链接与源码展开仍使用浏览器原生能力。

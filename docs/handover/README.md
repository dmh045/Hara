## 一、项目现状与交付边界

1. **已经有可运行的完整链路。** DOCX/PDF → 功能/失效 → 场景与自主物理 → 因果 → S/E/C/ASIL → SG、Safe State、FTTI → 保留模板格式的 Excel。普通分析与样本使用同一生产策略。
2. **五份输入均有历史真实分析及后续定向修订。** 最新完整修订共 2,389 条风险、2,071 条主表行、349 个 SG。当前有 2,068 条 C 数值、2,076 条 ASIL 数值；仍有 321 条 C、313 条 ASIL 没有数值。数值和工程批准是两回事。
3. **方法来源统一，项目事实与假设分开。** LLM 提出语义判断和物理假设，程序验证并执行活动方法；不允许模型直接决定最终评级或自行声明批准。
4. **本阶段交付具备工程审核用途，不等于正式发布全部完成。** 仍有方法适用范围、响应控制路径、完整场景覆盖与审核状态的限制，详见第 07 章。没有为了减少 Pending 将未知能力填成已知。
5. **仅拉取 GitHub 不等于拿到全部运行证据。** 运行 checkpoint、原始返回、账本和大部分报告位于被 Git 忽略的本地目录。交接必须同时完成代码、方法、输入和运行证据的移交。

本次整理只修改文档和导航，不修改算法、方法数值、审批状态或 `.env`，不启动付费请求与新全量。文档核查发现的现有约束也如实保留，例如原生 Windows 的文件锁兼容问题，以及普通全量 CLI 与有界样本的预算装配差异。

ASIL 有数值的数量略多于 C，是因为活动方法存在合法零级/QM路径；不应反过来给这些成员补造 C。具体评分资格与短路规则见第 03 章。

## 三、一页理解系统

```text
产品文档：告诉系统功能与范围
方法资产：告诉系统如何分析与评分
报告模板：告诉系统如何呈现
             ↓
来源事实与功能 → 失效 → 代表工况 → 物理方案/计算 → 具体因果
             ↓
同一对象、轨迹和阶段的 S/E/C → 活动矩阵 ASIL
             ↓
安全目标与关联响应 → Safe State / FTTI → Excel 与审计
```

三个容易误解的点：

- **场景数不等于请求数，也不等于主表行数。** 一个物理方案可能有参数取点和驾驶员分支；相同任务可以复用；报告按真实条件和评级组织审核组。
- **“待审核”不等于“没有算出来”。** 条件性数值可存在但尚未批准；没有数值则需要看具体缺口。
- **FTTI 不是直接把 TTC 改名。** 它需要相应响应路径和时间起点语义；能停车也不必然能避免移动目标碰撞。

## 五、术语速查

| 术语 | 本项目中的意思 |
|---|---|
| Item / Item Definition | 被分析系统的产品定义、边界、功能与运行条件 |
| ODD | 运行设计范围，含场所、道路、环境、模式及限定关系 |
| Function / Output | 功能职责 / 功能对外输出，不能只是同一段文字 |
| Guideword / Malfunction | 引导词偏差 / 由功能偏差形成的失效模式 |
| Atom | 方法资产中可识别的场景条件单元；需绑定适用范围和 E 依据 |
| 父场景 / 子场景 | 来源运行条件 / 明确对象、轨迹、参数和驾驶员后的具体分析世界 |
| 物理方案 | 选择模型、对象、参数假设与剩余控制能力的结构化建议 |
| 因果判断 | 该失效在具体条件下是否形成相应危险，而非仅凭参数存在就判危险 |
| S / E / C | 严重度 / 运行情境暴露 / 可控性；依据活动方法计算 |
| ASIL / QM | 风险等级或质量管理结果；由活动矩阵及其有效规则决定 |
| SG | Safety Goal，安全目标；关联危险事件，不能仅按语言相似任意合并 |
| Safe State | 安全状态；本报告必须区分目标、适用响应与已验证可达性 |
| TTC | 给定运动中的接触时间指标，依赖对象、轨迹与参考时刻 |
| FTTI | 故障容错时间相关分析；本程序需区分条件性响应时间边界与正式审核结果 |
| Checkpoint | 已原子保存的业务状态，用于恢复和复核 |
| 冻结响应 | 固定已有模型返回用于离线回归，不等于重新做过真实模型验证 |
| 精确复用 / 方案复用 / 完整因果复用 | 分别是同任务、物理建议、完整判断的不同复用层级，收益不能混算 |
| Provider | 应用实际调用的模型服务；其消耗与 Codex 开发/监控消耗分开 |

## 六、交接后的工作原则

先从一个真实身份贯通来源、方案、因果、评级和报告，再改对应的权威实现。保持单一运行时、单一方法契约、单一报告链；不新增只为样本成功的旁路。对新项目的合理动态条件可自动假设，对未知产品规格和方法范围要准确限定结论。成本优化用请求数、实际 Token、耗时和有效工况质量衡量，不能只看 Excel 行数变少。

接手者无需从历史数百轮对话重新推断这些约定；本手册各章已给出源码入口、现有证据和未完成边界。

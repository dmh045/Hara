修改顺序：

1. 保存真实首次请求/返回和程序诊断，先分清来源、结构、实例化、计算或展示问题。
2. 优先在既有职责修漏投影或矛盾契约，替换重复说明，不向长提示末尾无限追加警告。
3. 语义变化时更新相应prompt/视图/校验身份并验证缓存隔离。只改运动提示不应使无关CONTROL_ONLY缓存失效。
4. 新可选字段须兼容旧计划；SYMBOLIC不能被旧点值回补，RANGE不能静默变唯一点；PENDING不是批准。
5. 普通workflow、producer、compact因果输入、依赖指纹、评分和报告全部接通。仅有新字段或未调用函数不算完成。
6. 使用已有有限纠正，不新增无限修复层，不强制模型给true或预期ASIL。

身份权威为 [`ResponseCheckpoint.complete`](../../src/hara_agent/infrastructure/llm/response_checkpoint.py)，调度为 [`construct_physical_scenarios`](../../src/hara_agent/workflow/physical_analysis.py)，因果证明为 [`scenario_equivalence`](../../src/hara_agent/services/analysis/scenario_equivalence.py)。提示、方法政策、接口和缓存意义变化都是行为修改，不是纯清理。

## 5. 修改方法YAML

入口是 [`manifest.yaml`](../../method_assets/fusa_baseline_v1/manifest.yaml)、[`validate_manifest`](../../src/hara_agent/method_sources/yaml_validation.py)、[`YamlBaselineCompiler`](../../src/hara_agent/method_sources/yaml_baseline.py)。执行器只接收编译后的 [`MethodContract`](../../src/hara_agent/contracts/method_contract.py)，不直接打开YAML。

推荐步骤：

1. 查canonical role、normalized source和profile，确认是数值权威、条件约束还是仅参考。
2. 说明依据、适用范围、对象/阶段/控制及优先级，不按参考表ASIL分布倒推规则。
3. 业务规则放受治理资产，不在Python写C等级或备用ASIL矩阵。
4. 对已审资产按原字节重算asset_hashes，再编译。哈希只证明完整性，不是工程批准，不能用更新哈希掩盖未审方法变化。
5. 跑编译、边界、parity与同输入冻结响应对比，记录允许变化和不应变化的结果。

只读计算单文件哈希可用：

```bash
.venv/bin/python -c 'import hashlib,pathlib; p=pathlib.Path("method_assets/fusa_baseline_v1/normalized/project_analysis_policy.yaml"); print(hashlib.sha256(p.read_bytes()).hexdigest())'
```

它不会更新manifest，也不授权变更政策。

三个常见误区：

- **文件存在不代表执行。** 当前manifest排除了`raw/controllability_rules.yaml`、`raw/c_iso26262.yaml`作为数值权威，不能只改这些文件就称C已接通。
- **方法不是项目事实。** 项目决定应绑定输入内容和适用条件，不通过方法资产中的项目名识别新Item；[`scoped_odd_context/ItemDefinitionFacts.for_scope`](../../src/hara_agent/models/item_facts.py) 保留局部/全局证据。
- **允许范围不是当前工况。** 允许室内/外、上下坡、多车位不代表每个候选同时具备全部条件；17种请求焦点也不等于17种真实几何覆盖。

物理/响应公式同样经过MethodContract和适用性验证。真实未知产品能力局部列缺口；相容分析假设允许条件试算，不退回让用户逐行补距离、加速度和TTC。

## 6. 修改报告生成逻辑

配置是 [`hara_report_v1.yaml`](../../report_assets/hara_report_v1.yaml)，加载验证是 [`ReportSchema/load_report_schema`](../../src/hara_agent/services/reporting/report_schema.py)，生成职责是 [`HARAReportProjectionService`](../../src/hara_agent/services/reporting/projection.py)、[`EngineeringReportTextMapper`](../../src/hara_agent/services/reporting/engineering_text_mapper.py)、[`HARAReportWorkbookRenderer`](../../src/hara_agent/services/reporting/canonical_renderer.py)。不建固定坐标的平行报告器。

展示修改用已有checkpoint走 [`OfflineReportRebuilder`](../../src/hara_agent/services/reporting/offline_rebuild.py)，零Provider重导。检查：

- 原checkpoint与Excel保留；S/E/C/ASIL、来源/审批、风险与SG身份不因措辞改变。
- 主表一行一组完整评级，不拼接不同分支各列最大值。
- QM已知但其他成员未决时，不把全组说成QM；最高已知与全组结论分开。
- SG按实际成员关联，正文简明且有主语；原文/依据保留，不拼成新目标。
- Safe State写期望状态，控制路径和可达性分开；FTTI按路径展示最小已计算边界，未知、0、不能避碰不能混成一个样本范围。
- 速度最多1位小数，距离/加速度/TTC通常最多2位、去尾零；小非零不显示0、未知不变0。分档、缓存和风险身份用原精度。
- 等级格纯S/E/C/ASIL，审核/假设性质独立；动态等级、SG、Remark正文不合并。
- 可见叙述中文，MDC/IPB等缩写可保留，原始英文来源留审计。不能全表数字正则或全局外文折叠破坏来源限定。

必须看实际输出。至少检查场景、计算依据、物理明细、SG/Safe State/FTTI代表区域。静态合并文字可能居中在多行中间，截图要包含整个合并范围，别把裁切当空白。视图及依赖确实不变时可复用已核图，变化区域重新渲染并实际查看。

报告schema哈希与评分方法哈希不同。词表/布局变化应记录真实展示契约变化，不能改历史方法或批准身份来“对齐”。setup的example仓库URL/支持邮箱也只是包装占位，正式发布要更正，不当成真实业务来源。

## 7. 跨项目复用与工作量

关键入口为 [`select_source_blocks`](../../src/hara_agent/services/extraction/source_selection.py)、[`ItemDefinitionFacts.for_scope`](../../src/hara_agent/models/item_facts.py)、[`MethodScenarioCandidateService`](../../src/hara_agent/services/analysis/method_scenario_service.py)、[`PhysicalHypothesisInstantiationService`](../../src/hara_agent/services/analysis/physical_hypothesis_instantiation_service.py)。

修接线至少覆盖两种真实输入风格，并加重命名文件/功能、不同项目同失效ID、训练/执行、车内/车外/未知、不可用/未知控制等反例。不能靠F1、A5、parking或文件名猜能力。

完整非驾驶员世界先分配来源焦点，再按父谱系和样本scope过滤；样本只选范围/预算/记录。不用私有提示、手填物理输入或批准制造成功。不同对象、阶段、坡向、人员使能条件不能因评级相同合并。

分别统计精确复用、物理方案复用、共同证据、部分因果和完整因果；缩表不是少请求证明。新字段要检查生成→实例化→compact因果视图→计算→报告，不止加数据类字段。

## 8. 功能修复与纯重构分开

[AGENTS.md Safe code convergence](../../AGENTS.md) 要求每轮检查触及模块及直接caller的重复、废弃路径和副作用；每三轮完整修复或全量前做跨模块检查。没有证据可安全删除就保留，不以删行数交差。

| 版本 | 作用 | 验证 |
| --- | --- | --- |
| A | 原基线 | 保存错误及首次证据 |
| B | 功能修复 | 解释A→B必要变化，用反例和生产路径证明 |
| C | 清理后的B | 同输入/方法/配置/冻结响应/随机种子证明B→C等价 |

删除前查imports/re-exports、CLI、注册、配置/模板/skill字符串、序列化路径、旧checkpoint、回放、fixtures和文档命令。无引用、低覆盖、old/legacy命名都不是充分删除依据。

B→C比较数值、来源/审批、对象/阶段/坐标、身份/排除、异常、请求契约/次数、重试、预算/缓存、并发落盘和恢复；仅白名单明确的时间戳/路径等非业务差异。解释不了就回滚清理，不改断言掩盖。

薄兼容需写清消费者和退出条件。比如 [`HARAState.read_committed/from_dict`](../../src/hara_agent/workflow/state.py) 的历史只读与恢复语义不同，不能合并；[`scenario_with_current_physics`](../../src/hara_agent/services/analysis/scenario_equivalence.py) 的窄guard也不能扩成所有历史场景无条件重算。

## 9. GitHub交付和回滚

要求见[AGENTS.md](../../AGENTS.md)。先检查工作树，不reset/clean、不无关格式化：

```bash

```

完成受影响测试、全门禁及必要验证后显式选文件提交，不无差别`git add .`。功能用`fix:`，纯清理独立`refactor:`，文档说明清楚；核对远端/分支后普通push，不强推。

不应随意提交：

- `.env`、API key、SSH私钥、认证头、个人编辑器配置和机器锁文件。
- output/runtime的历史checkpoint、账本、原返回、缓存、报告和debug dump。
- 用户Item、参考工作簿、下载附件、压缩包、`.DS_Store`，除非另有明确受治理纳入安排。
- 含敏感信息的大临时数据。需冻结反例时用既有tests/fixtures，去凭据、写来源范围并核哈希。

[`.gitignore`](../../.gitignore) 未覆盖某文件不代表应提交；用户已有dirty文档不应顺手改写/提交。

回滚区分代码、方法、样式和历史运行。保留独立提交和依据，已推送修改优先新revert提交，不重写共享历史。业务输入或契约变化时保留旧run并新验证，不覆盖账本、不改真实响应，不删除旧结果来“恢复干净”。

## 10. 每轮交接留下什么

证据入口为 [`ReviewArtifactWriter`](../../src/hara_agent/workflow/review_artifacts.py)、[`CheckpointRepository`](../../src/hara_agent/workflow/checkpoints.py)、[`ProviderAttemptBudget`](../../src/hara_agent/infrastructure/llm/provider_budget.py) 和[统一关闭清单](../Reuse_Reporting_Closure_20261018.md)。沿用同一清单，不另堆互不对应阶段报告。

记录问题/根因、权威实现/caller、必要变化、安全删除依据或保留理由、测试/生产证据、输入/方法/模板/代码哈希、真实首次响应与纠正、实际调用/Token/时间、未覆盖范围和可回滚提交。

最后分开回答：代码改了吗，普通路径证明了吗，固定总体查了吗，真实模型测了吗，还缺什么方法/产品规格，技术上能否新全量，是否有预算。测试数、主表减少、Pending下降或新增类数量不能替代这些结论。
